# Working in the command centre

Add a project in **Programme**. The project owns the separate delivery, funding and co-op stages. Each desk uses the same project selector and search, and project pages link back to active tools. Open a record to read its signed versions. The empty workspace starts with no real organisations, facilities or relationships asserted.

| Desk | Tools |
| --- | --- |
| Programme | Project portfolio, upcoming commitments and milestones |
| Places and outreach | National Coverage, organisations, postcode opportunities and consented contacts |
| Sites and delivery | Candidate site briefs and work packages |
| Funding and finance | Funding pipeline and budget lines in AUD |
| Co-ops and handover | Co-op readiness reviews and management acceptance records |
| Media and CMS | Editorial drafts and review records, monthly media calendar |
| Records and decisions | Decision and evidence registers |
| Continuing operations | Operator register, maintenance and incidents |
| Webmaster | Your account, project-scoped read-only previews and recent signed changes |

Working registers take their distinct statuses and fields from the company plan. Link a candidate site to its organisation in the same project. Use a decision reference for recorded acceptance. Editorial review does not release material to an outlet. Evidence references record where evidence is held; file storage is a later feature. The calendar stores dated activities and supports month navigation.

Atlas navigation for the portfolio and the separate fictional walkthrough follow P4A's tool catalogue and scoped previews. Place research and the distinction between a lead and a consented relationship follow Outreach CMS. Structured registers and signed revisions follow the PLFC and Sandy workbenches. The demo is independently deployed and has no production database binding.
